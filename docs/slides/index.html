How it works

One brain, many sensors. A faster, cheaper brain over time.

Sensors

thin, one per OS, each through its sanctioned API

LIVEBrowser: selection, forms, reading. Phone: same Alter via QR.
NEXTmacOS Accessibility API · Windows UI Automation · Android Autofill + assistant role · iOS Safari extension + share sheet

Brain

the same everywhere

LIVEContext store: each fact has a source, a confidence, and an owner who can edit it.
LIVESafety rules in code, not prompts: passwords, payments and banks are never read.
LIVELearns how you like to be helped: open or pass, and goes quiet when you pass.

Models, cheapest first

most interactions never reach a cloud model

0Code: standard fields, rules. Zero cost, instant. Live
1OS on-device model: private first pass (strip personal data, classify). Apple Foundation Models, Android Gemini Nano (ML Kit GenAI), Windows AI APIs. Next
2Claude Haiku 5.5: explain, draft, decide. Live
3Larger Claude: only for hard tasks. As needed

Next for tier 2: specialized decision models (typed questions in, calibrated probabilities out) and fast diffusion language models, behind the same interface. Not used in this submission; every AI call in this demo is Claude.

⏱

Why now: every major OS now ships an on-device model to developers, and fast specialized models make "should Alter speak now?" cheap enough to ask constantly. The brain stays the same; each new device is a thin sensor, not a rewrite.
